# Revised SEAM figure decision — checkpoint composition

> Superseded after a second discussion: a pair-by-pair heatmap would largely repackage the existing encoder-choice table. See [the mechanism-figure decision](2026-09-25_mechanism_figure.md). The matrix remains an optional future generality experiment, not the recommended paper figure.

## Why the first proposal was demoted

A score-versus-visible-source-budget curve asks whether additional document text helps. It does not directly test the paper's distinctive claim that separately pretrained encoder and decoder checkpoints can be assembled through SEAM. It may be useful as an appendix robustness analysis, but it should not be the headline mechanism figure.

## Recommended research question and figure

Merge the current reference-quality and source-support questions into one overall-comparison RQ. Expand the existing encoder-choice analysis into a *pair compatibility* question: **Can the same SEAM interface design compose more than one independently pretrained encoder–decoder checkpoint pair, and how does it compare with direct cross-attention for each pair?** Do not claim plug-and-play inference-time swapping or reuse of interface weights: every pairing is jointly fine-tuned from its own initialization.

The main figure is two compact heatmaps with identical encoder rows and decoder columns. For a minimal pilot, use two already-tested encoders (PPLX-Embed-0.6B and Qwen3-Embedding-0.6B) and two Qwen-family decoder checkpoints (Qwen3-0.6B and Qwen3-1.7B), subject to checkpoint/code compatibility and compute. One heatmap shows the paired SEAM-minus-Direct-CA ROUGE-L difference; the other shows the same difference for SCALE. Annotate each cell with the absolute SEAM score and its paired uncertainty, or place absolute scores in a companion table if the cells become crowded. Decoder-only scores for each decoder checkpoint are separate references, not component ablations. Use the same dataset records, train/update budget, checkpoint-selection rule, and decoding within every pair. A larger four-encoder matrix can follow if feasible.

This makes two propositions visible at once: a nonempty cell means the encoder and decoder were successfully trained together on summarization pairs, and the sign/magnitude of the cell's difference tests whether the learned interface adds value beyond direct cross-attention *for that same pair*. Mixed signs must be shown. Current PubMed bridge ablation already demonstrates why: removing the bridge reduces ROUGE but increases AlignScore/SCALE, so a uniformly positive interface effect cannot be assumed.

## Data and scope boundary

Existing results cover four encoder choices with Qwen3-0.6B decoder on PubMed. No Qwen3-1.7B SEAM pair results are in the manuscript, and Direct-CA/no-copy rows are pending. The implementation uses a `QwenCrossDecoder` with Qwen-style decoder layers, so a Llama decoder should not be added to this matrix without engineering and validation. Two Qwen decoder sizes would test multiple checkpoints *within one decoder family*, not generality to arbitrary LLM architectures. Within-column comparison addresses decoder-size differences better than treating all absolute cells as capacity-matched.

## Cheaper mechanism-specific alternative

If additional decoder fine-tuning is infeasible, deepen the already-planned bridge/copy ablation instead of inventing a new RQ. Plot source-visible reference names/numbers correctly reproduced by full SEAM versus no-copy, stratified by actual encoder/decoder tokenizer-boundary disagreement; pair this with full versus no-bridge source-content coverage. The latter needs defensible evidence annotation, and exact string copying must not be described as factual correctness. A qualitative source-to-summary example may explain the route but cannot establish the aggregate effect.

## Decision rule

Do not draw heatmap values from existing aggregate tables. Finish matched Direct-CA and new decoder-pair runs, verify per-pair training and output provenance, then compute document-paired uncertainty. If improvement appears only in one pair or trades off strongly against source support, narrow the paper's composability/interface claim accordingly. If the additional training is too expensive, keep the current one-decoder encoder-compatibility table and use the cheaper targeted ablation figure without asserting decoder-swap robustness.
