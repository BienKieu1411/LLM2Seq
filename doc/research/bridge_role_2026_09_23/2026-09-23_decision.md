# Bridge role: test lexical value construction before another source router

Research only. No src modifications, model downloads, training or commits.

## Decision and corrected status

The user explicitly confirms XOV has not been tried. Prior exclusion based on
its existence in Git was wrong. Recommend evaluating that existing hypothesis
before replacing it with speculative covariance conditioning. Do not describe
this as a newly invented architecture or as an experimentally successful one.

Cross-attention already retrieves source information and learns K/V mappings.
A defensible complementary bridge role is to construct the representation
being retrieved: ordered lexical features of the source in the decoder's
tokenization. This is a finite-budget inductive-bias hypothesis, not a claim
that the contextual encoder and decoder cannot represent the same information.

## Verified historical XOV contract

At git revision efce6f8, src/xov_bridge/eviseq_xov/modeling/xov.py:

1. Let X = direct_projection(H0). Use X as memory for keys and copy_memory.
2. Tokenize the same visible source with the decoder tokenizer. Look up decoder
   vocabulary embeddings, RMS-normalize and project to rank 256.
3. Apply a depthwise width-3 convolution with separate left/right weights.
4. Reverse-scatter the features to encoder positions using overlap alignment,
   then apply SiLU and an up-projection to decoder width.
5. Smoothly cap the residual relative to X and form value_memory = X + g*delta.
   The up-projection starts at zero; the gate starts at 0.05, cap 0.20.
6. Use token CE only. The historical model passes original copy_memory into
   grounded_copy.prepare. No target text enters this source construction.

Keys/copy source tensors are unchanged for fixed encoder/embedding weights;
attention weights and output copy probabilities need not stay identical:
changed values alter decoder hidden states and later-layer queries. The shared
decoder embedding table also receives a new gradient route during training.

The role is lexical value enrichment, not generic encoder/decoder alignment,
region salience, coverage tracking, or hard phrase copying. Kernel 3 means
three subword tokens, not three words. Reverse overlap averaging can blur
ordered features when token boundaries do not align.

## Evidence and novelty boundary

- [Transformer](sources/01_transformer.md): attention reads a weighted sum
  of values, so constructing values and choosing where to read are separate
  operations in one layer. Contextual inputs prevent stronger incapacity claims.
- [ConvS2S](sources/02_convseq.md), ICML 2017, §3.3 Eq.2, adds source embeddings
  to values while using contextual outputs for keys; it reports benefits.
  This is direct architectural precedent, not proof for pretrained PubMed runs.
- [Primer](sources/03_primer.md) and [ConvBERT](sources/04_convbert.md) supply
  independent precedents for local composition alongside attention. Their
  interventions and objectives differ; they do not establish XOV effectiveness.
- [Local code](sources/09_local_code.md) establishes the actual contract and
  distinguishes XOV from the failed contextual region-value mechanisms.

Evidence is concentrated in academic papers plus this repository, not three
independent source types. The exact thesis "XOV raises ROUGE on this setup"
has insufficient evidence. Combining three indirect papers does not fix that.
Cross-tokenizer, ordered lexical values with separately preserved copy memory
is a potential implementation distinction. No exhaustive novelty claim follows.

## Strongest objections and falsifiers

1. H0 already contains lexical order. The bridge may be redundant and encourage
   unnecessary verbatim copying. Compare generated lengths, extractive bigram
   ratio and validation ROUGE under the same decoding budget.
2. Grounded copy already uses decoder lexical embeddings. XOV differs in
   feeding sequence-composed values into hidden-state computation before the
   vocabulary mixture, but complementary benefit remains unproven.
3. The failed contextual-value bridge warns that changing values is risky.
   XOV has a different signal, but an anchored residual does not guarantee
   preserved rankings, R1, R2, or RL.
4. Zero output initialization preserves the direct baseline initially, but
   first-step gradients into the convolution/down-projection are zero. Verify
   their gradients after the output projection has updated; do not label the
   expected first-step zeros a broken route.

Before an expensive run, audit source visibility, content masks, alignment
truncation, repeated-token scatter, empty alignment, cache reorder and DDP.
Verify g=0/direct-control forward parity, finite gradients after two updates,
and a change in value-memory direction after the decoder memory norm.
An isolated synthetic probe of the actual historical XOV module was run:
`probe_xov.py` loads its class from Git using fixture state/config types.
It verifies zero initialization identity, preserved key/copy memory, zero
padding and empty-alignment residuals. After one SGD update, a second backward
has nonzero gradients into lexical_down, phrase_conv, lexical_up and the gate;
the residual survives RMSNorm (delta norm 2.32e-5 in this tiny setup).
See `probe_xov_result.json`. The objective is a synthetic linear read of
normalized values, not teacher-forced CE. This is not an end-to-end test,
real-tokenizer test, pretrained-model test, DDP check or ROUGE evidence.

Integration boundary: current eviseq_new uses value_memory for copy preparation.
Historical XOV has a separate copy_memory field. A faithful port needs that
explicit bridge-output route preserved; simply replacing value_memory changes
copy features too. This is routing/plumbing for the bridge contract, not a new
grounded-copy algorithm, but must be included explicitly in any implementation
scope. No such code change was made here.

Train against a matched direct_projection+grounded_copy control with identical
model paths, data, source budget, prompt, global batch, update count, clipping,
seed, checkpoint choice and deterministic decoding. Compare with original
full too. If matched runs exist, reuse them only after checking these settings.
Use validation to select the design; avoid repeatedly choosing on test scores.
If XOV improves, kernel 1 vs kernel 3 distinguishes lexical bypass from ordered
composition. It is a follow-up mechanism test, not required to invent a result.

## Hypothesis decisions

H1: Linear mapping alone is weak motivation. Exact absorption into K/V is true
without intervening normalization, not generally for arbitrary maps before
this implementation's memory RMSNorm.
H2: Geometry conditioning remains underdetermined and is not selected. Whitening
can remove useful features; no actual checkpoint covariance problem was shown.
H3: Local lexical value construction is plausible and untested here; select XOV
as the next candidate. Do not invent a second local-filter name as novelty.
H4: A direct bridge may remain sufficient. Existing aggregate results are
consistent with this; no positive bridge gain can be promised.

## Synthetic probe provenance

probe_local_operator.py / probe_result.json test a separate neighbor-difference
KEY residual on tiny random tensors. They validate limited algebra/gradient
properties only, not XOV, not real models, and not ROUGE. That alternative is
not selected; preserve the files solely to prevent conflating tests.
