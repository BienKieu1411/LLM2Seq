# AFMR model integration audit for SEAM GRPO

Audit date: 2026-10-17. Scope is the existing `src/eviseq_new/eviseq_afmr` model, data, generation, checkpoint, runtime, and training APIs. The GRPO adapter lives in `src/seam_grpo/seam_grpo/` and does not alter the SFT implementation.

## Token alignment, EOS, and padding

The collator builds `decoder_input_ids = prompt + target`; labels are `-100` over the prompt and contain target tokens, including appended EOS. In the decoder, output position `t` predicts label position `t+1`. Therefore an action sequence of length `T` after a fixed prompt width `W` is scored from output positions `W-1` through `W+T-2`, i.e. `logits[:, W-1:W+T-1]`. The matching action IDs are the generated tokens themselves, including EOS.

The existing sampler left-aligns valid prompt tokens before decoding, appends the sampled EOS while its mask is still active, then appends padding with inactive masks for already finished rows (`evaluation/generate.py:143-145, 196-200`). It does not return that mask. The GRPO rollout returns an explicit boolean mask: it is true through the first EOS, including EOS, and false for later pads. If no EOS occurs, all tokens through `max_new_tokens` are active; rollout does not force EOS at truncation. Do not infer validity by comparing to PAD, since PAD may equal EOS and a padding ID may also be sampled before EOS on tokenizers where those IDs differ.

The rollout requires non-empty fixed-width prompts with all prompt-mask values true, matching the configured collator's fixed prompt. It uses the existing decoder cache for generation and clears the cross-cache in `finally`. TRL 1.16.0's `RepeatSampler` supplies contiguous `[source_0 candidate_0..G-1, source_1 ...]` rows directly to the subclass callback; the callback must not expand them again.

## Full action probabilities and normalization

Without grounded copy, `lm_head` returns ordinary unnormalized LM logits. With grounded copy enabled, `GroundedCopyHead.mix_logits` forms the probability mixture of the softmax LM distribution and source-copy distribution, but adds the LM log-normalizer back to each vocabulary score (`grounded_copy.py:94-103`). Thus the returned “mixed logits” are not normalized log-probabilities: `logsumexp(mixed_logits)` equals the base LM `logsumexp`. Always compute action probabilities with `log_softmax(mixed_logits.float() / temperature, dim=-1)` and gather the sampled token. The additive per-position offset cancels in this normalization, including after temperature scaling. The implementation uses this same normalization in rollout and gradient-enabled scoring.

Existing generation can additionally apply repetition penalties, no-repeat n-gram masks, minimum-EOS masking, top-k, and top-p (`evaluation/generate.py:171-195`, `_sample_token` at `:52-95`). Those settings alter the behavior distribution. The GRPO rollout intentionally sets all such transforms aside and samples only from `softmax(full_mixture_logits / temperature)`, so its saved `old_logps` and current-policy scores refer to the same full-support distribution. If those transforms are added later, their transformed distribution must also be used for the stored and current action log-probabilities; otherwise policy ratios are inconsistent.

## Gradient, dropout, budget, and cache behavior

For the current-policy pass, source encoding, bridge construction, decoder hidden states, copy keys/gate, and token scores must all be recomputed under autograd. `EviSeqAFMR.forward` connects these components directly (`modeling/model.py`); `Policy` preserves that route and checkpoints decoder work non-reentrantly before chunked vocabulary scoring. `SEAMActor` also checkpoints each candidate-row chunk inside its one DDP forward, avoiding retained encoder/bridge graphs for every candidate chunk. The copy state depends on bridge memory/source bias and decoder embeddings (`grounded_copy.py`), so reusing an inference rollout bridge would lose those gradients.

`generate_sampled` is decorated with `torch.inference_mode()` and calls `.eval()` (`evaluation/generate.py:97-125`). Rollout outputs are therefore detached; the new helper uses `no_grad` with inference mode explicitly disabled so the returned token IDs remain ordinary tensors suitable as later embedding indices. The policy action pass also puts the SFT model in eval mode while leaving autograd enabled. This keeps dropout behavior aligned with rollout. Do not call `prepare_cross_cache` for the differentiable pass: that method is `no_grad`, and eval-mode cross-attention consumes an existing cache if present (`modeling/decoder.py:138-140, 513-522`). The scoring pass clears any stale cross-cache and does not prepare another one.

The bridge controller consumes `output_budget`; rollout supplies the requested `max_new_tokens` when it encodes the source. The trainer attaches the same per-row budget to current-policy and gold-CE scoring so their bridge-conditioned distributions match rollout. `Policy` reads `batch["output_budget"]` and falls back to the model config only when that field is absent.

## DDP and integration constraints

TRL's accelerator wraps the `SEAMActor` (not a standalone `Policy`) for DDP. `actor.forward` performs candidate scoring and optional CE selection within one wrapped call; candidate chunks are internal to that call. The complete trainable tree is reachable as `actor.policy.seam`, while the native rollout helper receives that inner model directly and uses no gradients. This preserves DDP's normal synchronization over the encoder, bridge, decoder, and copy head without introducing a separate inference-weight synchronization path.

Keep gold CE on one selected row per source, not on all G-fold candidate rows. `SEAMGRPOTrainer` preserves the collator's decoder inputs/mask under `gold_decoder_input_ids` and `gold_decoder_attention_mask`, then builds prompt-plus-action inputs for policy scoring. `SEAMActor.forward` sums the selected rows' token-mean CE back to a token numerator; the trainer divides by the global gold-token count across ranks and the configured accumulation window.

Checkpoint loading is for the custom AFMR `.pt` checkpoint envelope, not a raw Transformers state dict. `load_checkpoint` validates architecture compatibility and known embedding shapes, then loads `state["model"]` strictly. Use the SFT resolved config to build the graph, pass `config=...`, omit optimizer/scheduler, and set `restore_rng=False` for an independent GRPO run (`training/checkpoint.py:132-171`).
