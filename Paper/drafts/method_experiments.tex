\section{Method}
\label{sec:method}

\subsection{Problem setting and design goal}
\label{sec:setting}

Let $x=(x_1,\ldots,x_S)$ denote a source document and
$y=(y_1,\ldots,y_T)$ its reference summary.  The system pairs a pretrained
source encoder with a pretrained causal decoder.  Their tokenizers, hidden
widths, and pretraining objectives may differ.  The encoder returns a final
hidden sequence $H^{(L)}\in\mathbb{R}^{S\times d_e}$ together with a small set
of intermediate sequences.  At each step, the decoder predicts $y_t$ from the
causal prefix $y_{<t}$ and source memory represented in its width $d_d$.

Two constraints shape the interface.  First, every source position that survives
tokenization and the length limit must remain available to cross-attention;
hard selection could discard an entity or number that the summary needs later.
Second, the interface must provide a controllable retrieval signal without
changing the content representation so much that the pretrained vocabulary
head or copy route loses its lexical anchor.  \EviSeq meets both constraints
with the \AFMR{} bridge.  The bridge returns a full source tensor for retrieval,
an aligned final-state tensor for values, and an additive source prior.  The two
tensors use the same source positions.  The design therefore has no pruned or
separately selected source bank and no target-derived evidence representation.

\subsection{\AFMR interface}
\label{sec:afmr-method}

\paragraph{Controller.}
The bridge summarizes the visible source and the fixed decoder instruction
separately.  Let $C\in\{0,1\}^S$ mark source content and let
$M_p\in\{0,1\}^{S_p}$ mark prompt tokens.  We compute
\begin{equation}
  \begin{aligned}
    \bar h&=\MaskedMean(H^{(L)},C),\\
    \bar p&=\MaskedMean(P,M_p).
  \end{aligned}
\end{equation}
Here, $P$ comes from the decoder prompt-token embeddings.  We RMS-normalize the
two means separately, project them into a controller vector
$c\in\mathbb{R}^{d_c}$, and add three quantities available at inference: the
number $N=\sum_i C_i$ of visible content tokens, the requested output budget
$K$, and their ratio.  Let $K_+=\max(K,0)$.  The base profile uses
$d_c=256$.  Its inference-only budget vector is
\begin{equation*}
  \phi(N,K)=\left[\begin{array}{c}
    \log(1+N)\\[-1pt]
    \log(1+K_+)\\[-1pt]
    K_+/\max(N,1)
  \end{array}\right].
\end{equation*}
The controller vector is then
\begin{equation}
  \begin{aligned}
    c&=\RMSNorm\!\big(W_h\RMSNorm(\bar h)\\[-2pt]
      &\quad +W_p\RMSNorm(\bar p)\\[-2pt]
      &\quad +\operatorname{MLP}(\phi(N,K))\big).
  \end{aligned}
  \label{eq:controller}
\end{equation}
The reference summary and its length never enter the construction of $c$.

\paragraph{Token-wise depth adaptation.}
The default bridge exposes the final four encoder states.  For source position
$i$ and tap $j$, let $\widetilde H_{i,j}$ denote the independently
RMS-normalized state.  A shared token scorer combines each tap with a
controller preference:
\begin{equation}
  \begin{aligned}
    \pi_{i,j}&=\Softmax_j\!\left(u_d^{\top}\widetilde H_{i,j}+(W_dc)_j\right),\\
    D_i&=\sum_{j=1}^{4}\pi_{i,j}\widetilde H_{i,j}.
  \end{aligned}
  \label{eq:depth}
\end{equation}
The softmax acts over depth for each source token, not over source positions.
We add a low-rank correction around the final-state anchor:
\begin{equation}
  H_i^*=H_i^{(L)}+g_d(c)\,B_d\,\operatorname{SiLU}\!\left(A_d
  [D_i-\widetilde H_{i,4}]\right),
  \label{eq:depth-residual}
\end{equation}
Here $A_d$ has the base-profile rank 128, $B_d$ starts at zero, and
$g_d(c)=0.15\,\sigma(\cdot)$ is initialized at 0.02.  Because the output factor
starts at zero, the initial memory follows the final-state path.  Gradients can
still reach the residual and, after an update, the depth scorer and router.

\paragraph{Cross-space feature adaptation and value anchor.}
The base map $\Pi$ is the identity when $d_e=d_d$; otherwise it is a trainable
orthogonally initialized projection.  The retrieval memory is
\begin{equation}
  \begin{aligned}
    Z_i&=\Pi(H_i^*)+G_f(c)\odot B_f\,\operatorname{SiLU}\\[-2pt]
       &\quad\left(A_f\RMSNorm(H_i^*)\right),
  \end{aligned}
  \label{eq:feature}
\end{equation}
Here $A_f$ and $B_f$ form the base-profile rank-256 correction.  The
feature-wise gate $G_f(c)=0.20\,\sigma(\cdot)$ starts at 0.02, and its output
factor also starts at zero.  The separate value anchor is
\begin{equation}
  V_i^0=\Pi(H_i^{(L)}).
  \label{eq:value-anchor}
\end{equation}
This lets $Z$ learn a retrieval-friendly representation while $V^0$ keeps the
final encoder content as its anchor.  The separation is a graph constraint, not
an assertion that the values stay fixed during full fine-tuning.  Shared encoder
and projection parameters still receive gradients through both paths.

\paragraph{Soft multi-scale source prior.}
\AFMR keeps every valid position and builds a relative prior from overlapping
content-token windows.  The base profile uses widths
$\mathcal W=\{32,128,512\}$ with 50\% overlap.  A task recipe may register a
different capacity profile, but the run manifest records the resolved
architecture and dimensions.  For each window, the controller and a scale
embedding score a masked mean of $Z$.  We center these scores within each
document and scale, lift them to tokens with overlap-add, and mix the available
scales.  The focus strength and temperature are bounded by
\begin{equation}
  \begin{aligned}
    \lambda(c)&=1.0\,\sigma(w_\lambda^\top c+a_\lambda),\\
    \tau(c)&=0.5+1.5\,\sigma(w_\tau^\top c+a_\tau).
  \end{aligned}
  \label{eq:focus-gates}
\end{equation}
The resulting score is $r_i=\lambda(c)\tanh(s_i/\tau(c))$.  For content
positions $\mathcal C$, we center the source bias with its log-mean-exp:
\begin{equation}
  \begin{aligned}
    b_i&=r_i-\log\left(\frac{1}{|\mathcal C|}
      \sum_{k\in\mathcal C}\exp r_k\right),\quad i\in\mathcal C,\\
    b_i&=0\quad i\notin\mathcal C.
  \end{aligned}
  \label{eq:source-bias}
\end{equation}
Cross-attention masks padding separately.  The prior changes relative source
preference, but it neither prunes the memory nor fixes the final attention mass.
All reductions in the focus path use FP32 before the bias is cast to the
attention dtype.

\subsection{Decoder source access and grounded copying}
\label{sec:decoder-method}

\paragraph{Copied cross-attention.}
Each causal decoder layer keeps its pretrained self-attention and applies a
copied cross-attention block afterward.  We initialize the query, key, value,
output, and normalization projections from the corresponding self-attention
modules.  For layer $\ell$ and target position $t$,
\begin{equation}
  \begin{aligned}
    h'_{\ell,t}&=h_{\ell,t}+g_\ell\,\mathcal A_{\ell,t},\\
    g_\ell&=\sigma(\theta_\ell),
  \end{aligned}
  \label{eq:cross-attn}
\end{equation}
Here $\mathcal A_{\ell,t}$ is multi-head attention with query
$\RMSNorm(h_{\ell,t})$, keys from $Z$, values from $V^0$, additive bias $b$,
and mask $M$.  The gate $g_\ell$ starts at 0.10 and is bounded by 1.0.  The
attention logits therefore contain $QK(Z)^\top/\sqrt{d_h}+b$ together with the
padding mask.  All layers receive the same source prior, while each layer keeps
its own query and output.  During greedy generation, the implementation
prepares the source keys and values once per layer and reuses them through the
cache.

\paragraph{Grounded copy and mixture likelihood.}
The copy head uses fast-tokenizer character offsets to align visible source
spans with decoder vocabulary tokens.  It pools contextual source keys,
combines them with lexical decoder embeddings, and computes decoder-query
attention over eligible aligned source-token rows $j\in\mathcal J$.  The same
offset weights pool the source prior into $\widetilde b_j$, giving
\begin{equation}
  A^{\mathrm{copy}}_{t,j}=\Softmax_{j\in\mathcal J}\!\left(
  \frac{q_t^{\top}k_j}{\sqrt{d_k}}+\widetilde b_j\right).
  \label{eq:copy-attn}
\end{equation}
Repeated source occurrences are then marginalized:
\begin{equation}
  P_{\mathrm{copy}}(v\mid t)=\sum_{j\in\mathcal J:\,\operatorname{tok}_j=v}
  A^{\mathrm{copy}}_{t,j}.
  \label{eq:copy}
\end{equation}
The learned gate $\rho_t$ mixes this distribution with the vocabulary head
applied to the decoder hidden state:
\begin{equation}
  \begin{aligned}
    P(y_t=v\mid y_{<t},x)&=\rho_tP_{\mathrm{copy}}(v\mid t)\\
      &\quad +(1-\rho_t)P_{\mathrm{LM}}(v\mid h_t).
  \end{aligned}
  \label{eq:mixture}
\end{equation}
The copy gate starts at 0.05.  When no eligible source token is aligned, the
model uses the LM logits exactly.  Alignment reads only the source and
tokenizers; it never reads the reference summary or evidence labels.

\subsection{Training, gradient flow, and inference parity}
\label{sec:training-method}

Training minimizes the token-level negative log likelihood of the mixture:
\begin{equation}
  \mathcal L_{\mathrm{CE}}=-\sum_{t=1}^{T}
  \log P(y_t\mid y_{<t},x).
  \label{eq:objective}
\end{equation}
The graph uses no contrastive, ranking, distillation, pseudo-reference, or
self-improvement objective.  During interface warm-up, the pretrained
backbones stay frozen while the bridge, copied cross-attention, and grounded
copy parameters learn from this loss.  Full fine-tuning then updates the
encoder and decoder jointly.  Parameters, gradients, and AdamW states remain
in FP32, while CUDA BF16 autocast handles the heavy operations.  The
implementation clips the global norm at the configured training threshold and
computes cross-entropy in chunks, so it need not retain a full vocabulary-logit
tensor.

The live gradient route is
\[
\begin{aligned}
\mathcal L_{\mathrm{CE}}&\rightarrow\{P_{\mathrm{LM}},P_{\mathrm{copy}}\}
\rightarrow\{h_t,Z,V^0,b\}\\
&\rightarrow\{\text{decoder},\text{AFMR},\text{encoder}\}.
\end{aligned}
\]
No detach is placed on $Z$, $V^0$, $b$, the depth mixture, or the controller.
The value-anchor separation constrains the direct route from the retrieval
residual to values, while encoder gradients still pass through both paths.

Teacher forcing and inference use the same encoder, prompt embeddings,
requested budget, \AFMR bridge, source memory, source prior, and copy
alignment.  Official evaluation uses one beam, no sampling, and autoregressive
argmax with \texttt{temperature=0}, \texttt{top\_k=0}, and \texttt{top\_p=1}.
These fields remain available for a separate candidate-generation path but do
not affect training.  The encoder and bridge run once per example; cached
cross-attention states then advance with the generated prefix.

\section{Experiments}
\label{sec:experiments}

\subsection{Research questions and comparisons}
\label{sec:rqs}

We evaluate the same questions on \PubMed, \ArXiv, \BookSum, and \GovReport.
RQ1 compares \EviSeq with fine-tuned decoder-only controls on source support.
RQ2 compares those systems and \TfiveGemma on overlap and semantic quality.
For RQ3, we train three ablations from the pretrained initialization with the
decoder held fixed: (i) no encoder, implemented as a decoder-only source-prefix
control; (ii) no \AFMR bridge, using the direct final-state projection with zero
source prior; and (iii) no grounded copy, using the complete \AFMR and decoder
path with only the vocabulary head.  RQ4 keeps the decoder and interface fixed
while replacing the anchor encoder \PPLXEmbed with \QwenCausal, \QwenEmbed,
and \NemotronEmbed.  Each RQ covers all four datasets.  A missing manifest or
failed run stays missing rather than being replaced with a score from another
split.

The decoder-only suite contains \QwenZeroSix, \QwenFour, \QwenEight,
\LlamaThreeTwoThree, \LlamaThreeEight, \NemotronThree, and \NemotronEight.
We fine-tune each model locally on the same source--target records.  We also
fine-tune \TfiveGemma on every dataset and use it as the encoder--decoder
reference.  For each ablation and encoder-transfer row, all non-target
components and optimization budgets remain fixed; the full baseline suite is
used in the main RQ1/RQ2 tables.

\subsection{Datasets and preprocessing}
\label{sec:datasets}

\PubMed pairs biomedical articles with abstracts, and \ArXiv pairs scientific
papers with abstracts.  \BookSum contains long narrative documents with
human-written summaries at multiple granularities \citep{kryscinski2022booksum},
whereas \GovReport contains long U.S. government reports with expert-written
summaries \citep{huang2021efficient}.  We will record each dataset's official
split and task variant in a manifest.  The repository currently provides
canonical JSONL preparation for \PubMed and \ArXiv; the \BookSum and \GovReport
manifests and field mappings are still pending, so this draft cannot report
their scores.

We normalize each record to \texttt{id}, \texttt{text}, and \texttt{summary}.
The encoder receives a fixed task prefix, the source, and a tokenizer-specific
special sequence.  The content mask removes the prefix, special tokens, and
padding from the depth and focus calculations.  Each task uses one fixed
decoder instruction, tokenized once and excluded from the supervised labels.
Every model in a dataset uses the same source and target length limits, and we
report truncation counts.  The model receives no reference text at inference.

\subsection{Metrics and statistical analysis}
\label{sec:metrics}

We use ROUGE-1, ROUGE-2, and ROUGE-L F1 as the primary quality measures.  One
Perl ROUGE-1.5.5 wrapper and one preprocessing procedure serve every system
\citep{lin2004rouge}.  Python ROUGE-1.0.0 is kept for debugging only and is
never mixed with the primary values.  BERTScore-F1 is the secondary headline
measure for semantic similarity; precision and recall are reported as
diagnostics \citep{zhang2020bertscore}.  The evaluator loads its backbone from
a local path and fails instead of downloading another model.

RQ1 uses the native consistency output of the local AlignScore
\texttt{nli\_sp} procedure.  For example $i$, we pair source chunks with each
generated claim sentence, keep the strongest support for each claim, and
average the claim scores to obtain $C_i=\AlignScore_{\texttt{nli\_sp}}(x_i,y_i)$
\citep{zha-etal-2023-alignscore}.  The dataset estimate is the mean of $C_i$,
with higher native consistency preferred.  For readability, we may also show
$H_i=1-C_i$ and its dataset mean as a lower-is-better, direction-transformed
hallucination-oriented value.  This transform is neither a probability nor a
calibrated percentage of hallucinated content.  We report the model/checkpoint
identifiers, maximum pair length, chunking, and sentence splitter for both
AlignScore and BERTScore.

For every paired comparison, we will compute a 95\% paired bootstrap interval
over identical test IDs and report the number of examples.  The dataset-level
estimate is the mean over its examples.  The secondary four-dataset macro
estimate is the unweighted mean of the four dataset-level effects, with a
dataset-aware interval.  We report dataset rows first and leave the macro value
pending when any dataset is missing.  Each research question has one
pre-registered primary endpoint; other metrics and model contrasts are
exploratory unless we specify a multiplicity adjustment.  We will also record
generated and reference lengths, length ratio, empty and truncated outputs,
repeated-trigram rate, unique-output rate, source-copy rate, and, when
available, a manually audited factual-error subset.  These diagnostics show
whether an apparent factuality gain could instead come from shorter or empty
outputs.

\subsection{Fairness, implementation, and reporting}
\label{sec:fairness}

Within a dataset, all main models use the same split IDs, source and target
budgets, preprocessing, seed policy, optimizer family, number of effective
training examples, and greedy decoding constraints.  We record each model's
native source and decoder serialization explicitly; a shared task instruction
does not make tokenization or chat-template behavior identical.  The \AFMR
recipe uses interface warm-up followed by full fine-tuning.  We match the
number of optimizer updates to the corresponding baseline instead of inferring
it from wall-clock time.  The reported checkpoint is \texttt{last.pt}; test
scores never select a best checkpoint.  We record batch size and accumulation
for each model and dataset so the effective batch is clear.

The experiment manifest will record local model paths or immutable revisions,
tokenizer special IDs, prompts, source and target limits, seeds, total and
trainable parameter counts, precision, software versions, GPU type, peak VRAM,
training time, generation time, failed runs, and output-file checksums.  A score
cell is valid only when its prediction manifest and metric JSON agree on the
dataset split, example IDs, checkpoint, tokenizer, scorer, and decoding
settings.  The four-dataset tables in Section~\ref{sec:results} remain blank
until these checks pass.
