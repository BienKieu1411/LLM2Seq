# Source-conditioned Adaptive Norm bridge

This is an independent bridge experiment built from the `eviseq_new` recipe.
The source encoder, full cross-attention memory and grounded-copy output head
are retained. The new contribution is a source-conditioned controller consumed
by a low-rank adaptive norm in every decoder layer.

```text
encoder H -> width projection M ------------------------> decoder cross-attention
       \-> source/prompt/budget controller -> adaptive norm -> decoder self-attention
M + source alignment -----------------------------------> grounded copy / LM CE
```

The controller is a 256-dimensional summary of the visible encoder source, the
decoder prompt and the requested output budget. In each decoder layer, the
normalized hidden state receives a low-rank scale/shift generated by that
controller. The scale and shift output projections start at zero, so the full
graph is exactly equal to direct projection at initialization. A bounded gate
and relative-RMS cap limit the perturbation during the first updates. The cap
coefficient is detached; gradients still pass through both output projections
and, after the first update, back to the controller and encoder.

Training uses the same token-level cross-entropy objective as `eviseq_new`.
Candidates are never generated during training, and salience/evidence losses
are rejected by configuration. Grounded copy remains enabled by default and
uses the unchanged projected source memory, which isolates the bridge effect.

## Full and ablated runs

The base recipe is in `configs/afmr_pubmed.yaml` and uses
`architecture.bridge_mode: source_film`. The controlled ablation uses the same
config with `bridge_mode: direct_projection`; the runner automatically disables
the adaptive norm for that condition.

On the server, set local model paths and run the PPLX encoder on one GPU:

```bash
cd /workspace/storage-shared/nlp/dungdx4/bien_projects/LLM2Seq
CUDA_VISIBLE_DEVICES=0 \
AFMR_ENCODERS=pplx \
AFMR_ARCHITECTURE=source_conditioned_adaptive_norm \
AFMR_BRIDGE_MODE=source_film \
AFMR_GROUNDED_COPY=true \
PROCESSED_DATA_DIR="$PWD/src/eviseq_new/datasets/pubmed" \
AFMR_OUTPUT_DIR="$PWD/runs/full_source_film_$(date +%Y%m%d_%H%M%S)" \
bash src/afmr_source_film/scripts/run_pubmed_pair.sh
```

For `w/o bridge`, change only `AFMR_BRIDGE_MODE=direct_projection` and use a
fresh output directory. The runner evaluates `last.pt`, not `best.pt`, and
keeps the encoder/decoder prompts, data processing, decoding settings and CE
recipe fixed.
